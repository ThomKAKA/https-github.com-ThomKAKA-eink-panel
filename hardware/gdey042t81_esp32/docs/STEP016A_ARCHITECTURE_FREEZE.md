# STEP016A Architecture Freeze

冻结日期：2026-09-13。范围：离线 Progress 页面第一版的设计与测试计划，未实现、未编译、未进行新的实机实验。
起始 HEAD：`85e2c4bb64561e55d27b42f215e1235b123a6ae8`。

## 1. 产品第一版目标

**Product Goal**：将本地 JSON 中的任务进度通过既有 Python ProgressPanel 生成可正常阅读的 400×300 电子纸页面，验证真实业务内容、中文字体及方向。第一版是人工更新的单页快照，不是长期联网看板。

**Scope**：Local JSON 输入、既有数据模型和 Pillow 渲染、正常阅读预览、离线 raw 打包、构建时嵌入完整位图、独立显示入口、每次启动至多一次标准 FULL、失败停驻。更换 JSON 后重新生成及编译，未来烧录必须单独批准。

**Non-goals**：网络、HTTP、轮询、传感器、SD/文件系统读取、串口传帧、多页面切换、实时钟、Partial/Fast Refresh、Deep Sleep、自动重试、异常自动恢复及长期稳定运行。当前不创建这些功能的代码或分支。

## 2. 第一版显示内容定义

复用 [ProgressPanel](../../../panels/progress.py) 的 `ProgressPanelData`，不新增公开字段或 MCU 端业务模型。

| 字段 | 第一版含义/显示位置 |
| --- | --- |
| title | 左栏任务类别标题，沿用现有大写呈现 |
| progress | 0–100 的百分比和进度条 |
| current_step | 当前步骤；左栏步骤及未来右栏主标题 |
| status | 右上状态标签 |
| description | 右栏说明文字 |
| tags | 最多显示两个标签，沿用现有容纳规则 |
| source | 右下数据来源 |
| updated_at | 右下快照时间，不是实时钟 |

未来最小渲染调整：普通业务页面右侧固定标题“改确认页位置”替换为 `current_step`；为空时采用明确的“等待数据”占位，保留 WAITING DATA / UPDATE FAILED 的既有提示语义。本轮不修改渲染器。
显示内容分为左栏进度主体、右栏状态/步骤/描述/标签、右下来源与快照时间，不另造 Header/Main/Footer 模板。

## 3. 数据来源设计

**Data Provider**：复用 [Local JSON adapter](../../../adapters/local_json.py) 与既有 Panel 校验/规范化契约。输入为 UTF-8 JSON 对象，字段见第 2 节；[现有本地样例](../../../data/local/progress.json) 用作结构参考，不直接视为冻结测试快照。
Mock 仅供测试；HTTP adapter、事件入口及服务端刷新调度不进入离线硬件路径。沿用 [既有架构](../../../docs/ARCHITECTURE.md)，不重新设计业务服务。

更新周期：无周期任务，由用户人工触发一次生成。第一版没有浏览器 Refresh 到设备的自动联动，也没有热更新；新的数据需要新的冻结产物和另行批准的实机步骤。

```text
Local JSON
  → 校验/规范化（要求显式非空 updated_at）
  → Python ProgressPanel / Pillow
  → 正常阅读的 400×300 1-bit 页面预览
  → 导出边界 Y 预翻转 / raw 打包
  → 15,000 字节传输帧 / 构建时嵌入
  → 独立专用显示入口 → 固定 H1 Y mirror → 一次标准 FULL → MCU 停驻
```

这是待实现数据流，不是当前可执行工具链。未来导出层必须在渲染前拒绝缺失快照时间，不能依赖现有 renderer 的系统时间回退而声称重复生成一致。
文件缺失、JSON 解析错误、Panel 语义错误或字体/布局验收失败：停止发布，不覆盖最后有效产物，不自动生成固件或烧录。等待/错误页面可做受控测试样例，但不能把无效输入静默转换成有效业务快照。

未来交付包括正常预览、raw 帧、嵌入数据与外部 manifest。记录输入、实际字体文件、生成环境和产物 SHA-256；自身哈希不写回被哈希文件。中间候选产物全部验证后才发布为有效集合，防止新预览搭配旧帧；具体工具实现另行评审。

## 4. 页面布局冻结

沿用 [设计系统](../../../docs/DESIGN_SYSTEM.md) 和现有 ProgressPanel 几何，不改变为上下四区。像素坐标范围 x=0..399、y=0..299，以下区域为现有布局约束：

| 区域 | 坐标/尺寸 | 字体与图形 |
| --- | --- | --- |
| 外框 | (0,0) 至 (399,299) | 1 像素线 |
| 内容 | x=10..389，y=10..289 | 内边距 10 |
| 左栏 | x=10..150，宽 141 | 黑底；类别标题、百分比、步骤、14 像素高进度条 |
| 间隔 | x=151..158，宽 8 | 留白 |
| 右栏 | x=159..389，宽 231 | 状态、步骤主标题、描述、标签、终端标记 |
| 右栏 footer | 来源 y=265；时间 y=277 | 沿用 8 像素字号，字形实际边界需测试 |

字号沿用 8/10/13/18/24 与百分比最大 64 的既有体系；百分比缩小规则不重写。字体选择仍由 Python 负责。必须记录实际字体路径/版本或文件哈希，确认中文覆盖；字体缺失、替换导致差异、字形越界或难读均在发布预览前拦截，不默认为通过。现有 renderer 并不保证所有长文本都自动适配，这是未来软件验收项。
所有区域同属一个完整帧，第一版刷新区域始终为全屏，不因区域划分引入局刷。

### 三个坐标边界

- 页面逻辑帧 L：左上原点，x 右、y 下，正常阅读预览。
- 传输帧 T：导出层预翻转，`T(x,y)=L(x,299-y)`。
- 面板物理帧 P：正视屏幕、FPC 朝下、左上原点；固定 H1 对 T 执行 Y mirror，因此 `P(x,y)=T(x,299-y)=L(x,y)`。

保留 [H1 适配器](../src/h1/atomic_display.h) 的 `mirror_y=true` 及其输入位图到面板 Y mirror 结论，不修改 H0/H1 显示方向代码。
两次翻转分别属于页面到传输与传输到物理的不同边界；禁止额外 rotation、再次行逆序或隐式 EXIF 变换。组合恒等是设计预期，正常文字与非对称标记仍须未来实机验证。

raw 格式沿用 [Frame Transport v1](FRAME_PROTOCOL.md)：400×300、row-major、MSB-first、0 黑 1 白、stride=50、精确 15000 字节，无 PNG/BMP 文件头。格式不变；本次不实现其候选 HTTP 接口。

## 6. 刷新策略规划

第一版纳入标准 FULL：每次启动至多一次，用于初始页面及下一次独立批准的整页变化实验。成功正常路径完整准备 0x26、0x24 后执行普通 FULL，fast-full 显式禁用；不为初始化先清屏。
刷新返回后无任何 EPD 命令，无 RAM 重写、powerOff、hibernate、清屏、重试或循环刷新；MCU 侧记录并延时停驻，不宣称已休眠。重启会重新执行，不是跨重启永久一次。
输入/准备拒绝不刷新；超时或返回状态不明只记录并停驻，屏幕最终状态 UNKNOWN。耗时和 BUSY 后置条件不是物理显示成功证据。

Partial Refresh / Fast Refresh：不纳入，避免引入未经验证的波形、残影和历史帧状态需求。
Deep Sleep：不纳入，未验证控制器/MCU 状态、供电保持和唤醒行为；不能用电子纸图像保持证明休眠。
无自动异常恢复；未来恢复动作必须另行评审，不能把 H1 的返回后零显示命令承诺推广到尚未设计的连续运行状态机。

## 7. 测试计划冻结

以下均为未来验收，不因本设计提交而标记运行通过。

| 测试层 | 案例 | 通过条件与边界 |
| --- | --- | --- |
| 数据模型 | progress 0/100、缺字段、无效类型/范围、非法 JSON、空时间 | 沿用语义校验；无效生成拒绝，不覆盖有效产物 |
| 可复现性 | 固定 JSON/时间/字体/工具版本重复生成 | 预览像素、raw 与嵌入数据一致；不要求不同字体环境盲目同哈希 |
| Renderer | 中文缺字、长标题/步骤/描述、百分比、标签、来源/时间 | 预览人工可读与自动边界检查；current_step 主标题符合规则 |
| 页面生成 | 正常、等待、错误测试样例 | 无效业务输入不被静默发布；受控异常样例与业务产物分开 |
| 帧编码 | 尺寸、长度、MSB 位序、黑白、四角及非对称标记 | 完整解码与预期一致，无头部或额外 padding |
| 方向 | L→T→P 仿真与独立预期比较 | 恰好一次导出预翻转和一次固定 H1 mirror，合成恒等 |
| 构建隔离 | 默认两环境与专用入口；私有配置缺失/错误 | 默认保护不变；专用输入失败即拒绝，未引入网络/轮询 |
| 静态执行 | 初始化/准备/最终 FULL 与返回后调用链 | 0/0/1 激活，返回后零显示命令；不冒充真实 SPI 计数 |
| 回归 | 项目 Python 125 项基线及新增用例 | 既有测试不回归；新增测试另报数量；主机 C++ 不可用时 BLOCKED/NOT RUN |
| 硬件 FULL | 新业务页面、中文、非对称方向锚点、前后不同内容 | 单次启动过程观察与最终照片共同记录；实机步骤另行批准 |
| BUSY 故障 | 超时注入、无效后置条件、后续命令计数 | 独立安全方案批准后测试；未注入不得宣称故障路径 PASS |
| 异常恢复 | 数据生成失败、设备失败、下一次启动 | 软件不发布坏帧；设备失败停驻；自动恢复不在第一版 |
| 后续专项 | Partial/Fast、Deep Sleep、长时间运行 | 各自定义时长/波形/功耗/故障标准后另测，不沿用 H0/H1 PASS |

硬件验收需保存实际固件哈希、上传证据来源、刷新过程用户观察和最终照片。选择不同于旧图的业务内容，不能仅靠同一保持画面的前后照片证明新刷新。热、电气安全不能从正常画面推断。
