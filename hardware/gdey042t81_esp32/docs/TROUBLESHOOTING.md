# 故障隔离

通用原则：停止刷新 → 记录症状与 Serial → 断电检查接线 → 一次只改一项。
不要通过连续重刷、反复切换多个 GPIO 或试探 5V 来排错。

| 症状 | 优先怀疑 | 检查顺序 |
| --- | --- | --- |
| 完全不动 | 配置保护、没运行固件、供电/CS/RST 错误 | 先查 `CONFIG_UNCONFIRMED` → 板/串口/固件 → 电源/GND → 逐根信号 |
| 全白 | 数据未写入、MOSI/DC/CS 或 FPC 接触 | 先运行 H0，排除 raw 位序 → 看 Serial/BUSY → 断电查接线/FPC |
| 全黑 | 极性、错误屏型、图像格式或接触问题 | H0 是否也黑 → 型号/GxEPD2 类 → 供电 → H1 的 0=黑/1=白 |
| BUSY 卡死/Timeout | BUSY 引脚错、FPC/供电、屏型不符 | 停止重试 → 查型号与 BUSY 线 → 地/电源 → RST/FPC；不要移除 BUSY 检测 |
| 左右颠倒 | 位序或方向不符 | 先 H0 方向 → H1 非对称角标 → 检查 MSB first；不要同时改多处 invert/mirror |
| 上下颠倒 | 行顺序/旋转设置 | 确认 H0 → H1 原点为左上，行从上到下 → 不得把 BMP 的文件行顺序当 raw |
| 乱码/花屏 | 数据长度、SPI 接触/信号、格式不符 | 先 H0 → FPC/线长/共地 → 15,000 字节 → 只尝试降低本地 SPI 时钟一项 |
| 只刷新部分区域 | 错误尺寸或裁剪/窗口 | H0 四边 → 400×300 与 row stride=50 → H1 全幅，不启用 dirty rectangles |
| 残影严重 | 快速刷新累积、温度或屏批次差异 | 关闭演示 → 普通 FULL → 室温/型号 → 降低 fast 次数、拉长间隔，一项一测 |
| ESP32 重启 | 电源不稳、线缆、错误目标或看门狗 | 保存复位原因 → USB/电源 → 板型与端口 → 再检查 SPI；不先引入 Wi-Fi 调试 |
| FPC 接触不良 | 未到底、偏位、方向错或损伤 | 断电 → 按该接口说明解锁 → 核实触点方向 → 平直插入锁紧；损坏时停止 |

GxEPD2 在 BUSY 等待超时会输出 `Busy Timeout!`，但刷新方法没有成功/失败返回值。
本骨架只能补查 BUSY 是否仍高，不能识别所有断线或像素错误。
依据 [上游 BUSY 等待实现](https://github.com/ZinggJM/GxEPD2/blob/de82887e77a78528ea386e68bba2cb0291d2c319/src/GxEPD2_EPD.cpp)。
即使 Serial 输出 Submitted，也必须目视验证；若 BUSY 误接导致恒低，日志可能看似正常。

未来网络失败时应保持最后完整有效帧，不在失败路径清屏或显示闪烁错误页；当前网络未实现，
所以现阶段的显示故障不能归因于 HTTP 或事件 API。
