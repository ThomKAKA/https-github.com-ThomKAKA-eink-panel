# 外卖页语义（P5）

> 本文件定义外卖页的字段、状态机与「超时」的判定方式，代码与测试以这里为准。

## 一单外卖

| 字段 | 规则 |
| --- | --- |
| `id` | `A-Za-z0-9_-`，1–32 位；同一页内唯一 |
| `name` | 店名或餐品摘要，1–20 字 |
| `status` | `waiting`（待取）/ `delivering`（配送中）/ `arrived`（已到） |
| `expected_at` | 可选，预计送达 `HH:MM`（24 小时制，必须补零） |
| `note` | 可选备注，最多 8 字；屏幕上显示在右侧 |

- 一页最多 6 单，超过写入返回 422。
- 屏幕上的「超时」不是存储状态，而是**自动判断**：状态不是「已到」、填了预计时间，
  且 Host 当前时间已经晚于预计分钟时显示「超时」。刚好等于预计分钟不算超时。
- 没有填预计时间的单永远不会超时；「已到」永远不超时。
- Host 在渲染时把当前 `HH:MM` 注入页面数据（同 `day_key` 的做法），保存的文档里不含
  当前时间；同样的文档 + 同样的分钟，渲染字节完全相同。
- 只有内容真的变化才换帧：每分钟会重新计算一次超时，但 ETag 不变时设备仍收到 304。

## 状态机

- 允许：`waiting → waiting / delivering / arrived`，`delivering → delivering / arrived`，
  `arrived → arrived`。
- 不允许回退或跳过已到的状态；非法变更通过 POST 接口返回 422，且不写入。
- `/manage` 编辑器的状态下拉框只列出当前状态和允许的下一状态；删除后重新添加可以纠正
  录错的数据。

## 接口

### `POST /api/takeout/orders`

手机快捷指令/脚本用它创建或更新一单，请求体就是一单的字段：

```json
{"id": "t1", "name": "牛肉面", "status": "delivering",
 "expected_at": "12:30", "note": "放前台"}
```

- 按 `id` upsert：新 `id` 追加，已有 `id` 更新名称/时间/备注并校验状态前进。
- 成功返回 `{"ok": true, "page": "takeout", "revision": N, "updated_at": "...", "order": {...}}`。
- 非法字段或非法状态变更返回 422；并发写冲突返回 409（带有当前文档）。
- 每次成功写入使 revision +1；设备最迟在下一轮 60 s 轮询时取到新帧。

### 页面接口

- `GET /api/pages/takeout`：读取当前文档（空页为 `{"orders": []}`）。
- `PUT /api/pages/takeout`：整页保存，用于 `/manage` 编辑器；写入前会先做渲染校验。
- `POST /api/pages/takeout/preview`：用草稿数据生成 400×300 预览，返回的
  `X-Frame-Version` 与设备下一次会取到的帧一致（同一分钟内）。

## 屏幕

- 页头：`外卖`、`TAKEOUT`、`N单`、日期与星期。
- 每行两行文字：第一行是状态与预计时间（13 px 加粗），第二行是名称（13 px）
  和备注（10 px 加粗）。
- 排序：超时 → 配送中 → 待取 → 已到；同组按预计时间、再按 `id`。
- 空状态：`暂无外卖订单` + `在 /manage 添加外卖单`。
- 页脚：`来源 / takeout rN`、`更新 / ...`（10 px 加粗）。

## 限制

- 不做推送通知、平台账号对接、取消/退款状态；只表达「当前这几单到哪一步」。
- 单设备、单热点；设备离线时保留最后一帧。
