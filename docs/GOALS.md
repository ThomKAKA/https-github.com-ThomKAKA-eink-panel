# E-Ink 信息屏 v1：可持续目标

> 本文件是主线目标的唯一说明。每次继续执行项目，先读本文件的「启动清单」和
> `PROJECT_STATE.md` 的最新阶段段，再动手。

## 0. 启动清单（每次继续执行前）

1. **先读**：本文件 + `PROJECT_STATE.md` 最新一段 + `git log --oneline -5`。确认当前阶段、
   验收门、未收口事项，不凭记忆开新坑。
2. **第一性原理**：先核对物理/协议事实（帧契约 15000 B、SHA-256 ETag、60 s 轮询、
   NVS 键、数据源可用性），再选最小实现。事实以代码、日志、真机证据为准，不以文档愿望为准。
3. **不防御性编程**：不加无依据的兜底分支，不搭建用不到的抽象，不为假想场景增加复杂度；
   错误路径只保留契约已经要求的部分（超时、LKG、409、503 帧不可用）。
4. **一个增量**：一次只做一页或一个修复；完成即验证、记录、提交；不可逆操作单独确认。

## 1. 一句话目标

到 v1，同一台 Host、同一份帧契约下，400×300 墨水屏稳定切换 6 个页面
（Progress、Memo、Course、Weather、Calendar、Codex），由 PWA 管家编辑与选页；
数据源故障时保留上一版画面并标记 stale；设备端保持零业务逻辑、零本地业务数据、零动画。

## 2. 现状基线（2026-11-08，已验收）

- 渲染：Host 用 Pillow 生成 15000 B `epd-t-400x300-mono1-msb-v1` T 帧；设备校验长度、
  格式、SHA-256 后整屏刷新。物理验收 PASS（Progress / Memo / Course）。
- 轮询：设备每 60 s 取帧；内容不变返回 304；切页后 ≤2 个轮询内完成一次 200 + 一次整屏刷新。
- 发现：Host 以 1 Hz 重播 `_eink-panel._tcp`，设备约 1 s 监听窗口内可发现；热切换端口已实测。
- 计数：固件 `round2-r6-3` 在整屏刷新完成后累加 NVS 计数并上报 `refresh_count`；
  304 不增加。真机从 4 连续验证到 7。
- 配网：长按 S1/KEY1 约 2 s 进入 `eink-panel-setup`，`POST /configure` 试连成功才保存；
  改 SSID 必须重新配网。
- 页面仓：`data/pages/*.json`（gitignored）+ 原子写；`progress` 为事件页，`memo`/`course`
  为文件页；选页状态持久化。
- 测试：Python 518 passed、前端 47 passed。
- 未收口：本地 `9636407`、`f55ff9f` 两个提交领先 `origin/main`；BUSY 注入 B1–B11 仍阻塞。

## 3. 架构边界（不动的部分）

- 渲染留在 Host；设备只做「取帧—校验—显示—上报」。
- 帧契约、200/304、ETag、LKG、60 s 轮询、mDNS、OTA、配网流程不变。
- 新功能只改 Host 与 Web；任何页面都不改固件。
- 设备端时钟/本地数据/本地渲染/动画不在 v1；若要做，另立项目并重新评估固件架构。

## 5. v1 范围

**必须交付**：Weather、Calendar、Codex 三页；Memo/Course 的既定增强；PWA 可用；
每页通过统一验收门。

**可选（必须项全部 PASS 后）**：外卖页；Android WebView 壳；宠物静态页。

**明确不做**：设备端 NTP/本地数据/本地渲染、宠物动画、局刷、云端、多设备、
分钟级倒计时、emoji 渲染。

## 6. 分阶段路线

每个阶段都是一个可独立演示、可整体回滚的增量。工作量 S≈半个会话，M≈1–2 个会话。

### P0 收口（S）

- 交付：本文件；`PROJECT_STATE.md` 记录目标文档。
- 收口项：两个本地提交是否推送，等用户明确授权；BUSY B1–B11 保持独立线，不混入主线。
- 退出：文档提交（如获授权）；工作树干净。

### P1 天气页（M）

- 交付：`panels/weather.py`（模型 + 确定性渲染）、抓取器（长沙、8 小时/3 天、超时、
  系统 CA、失败返回 LKG + stale）、整点刷新调度、`/manage` 编辑器、预览、测试。
- 退出：真机 200→304，断网保留上一帧且标 stale，计数只 +1。
- 依赖：选定一个稳定的天气 HTTPS 源；证书走系统 CA，不做自签例外。

### P2 日历页（M）

- 交付：月历版式；农历、二十四节气、节假日/调休数据表（钉版本）；当日高亮；按日切帧。
- 退出：3 个测试日期（含节气、节假日）渲染正确；真机 200→304。
- 依赖：农历/节气算法或离线数据表；节假日需年度维护。

### P3 Codex 用量页（M）

- 交付：新页面（额度、今日/累计 Token、占比、更新时间）；PC 同步脚本把真实数据写入页面仓；
  旧 `panels/stats.py` 只作视觉参考。
- 退出：数字来自真实同步（非静态样例）；15 分钟未更新标 stale；真机 200→304。
- 依赖：本机 Codex 用量数据源；同步脚本失败时保留上一帧。

### P4 Memo / Course 增强（S–M）

- 交付：课表固定 5 节次模型与「临时新增一节课」；倒计时语义定稿（日级，不做分钟级）；
  文档明确 emoji 不支持。
- 退出：模型/渲染测试全绿；真机验收现有页面不回归。

### P5 外卖（可选，M）

- 交付：页面（待取/配送中/已到/超时）、`POST /api/takeout/orders` 接收、状态机、编辑器。
- 退出：接口→页面→真机链路 PASS；无订单时显示空状态。

### P6 PWA / WebView（可选，S）

- 交付：安装体验、Host 地址配置、Android WebView 壳 + 真机测试。
- 退出：真机安装并打开 `/manage`，编辑与选页可用。

## 7. 统一验收门（每页同一张清单）

1. 模型 `extra="forbid"` 且有明确上限；同输入渲染字节确定（无隐藏时间/随机）。
2. `/manage` 可编辑、可预览；预览 PNG 与设备帧 SHA-256 一致。
3. 真机：切页后 ≤2 个轮询内 `200` + 15000 B + 固定格式 + ETag=SHA-256；下一轮 `304`；
   刷新计数每次内容变化只 +1；设备报告匹配；旧 ETag 返回 409。
4. 数据源失败：返回 LKG 帧并标 stale，不发布残缺帧。
5. Python 与前端测试全绿，新增模型/渲染/API 测试；证据与 `PROJECT_STATE.md` 追加。
6. 无凭据入日志；不改 NVS/分区；页面开发不刷机。

## 8. 可持续规则

- 一次一页；一个提交集只含一页，可整体 revert。
- 内容变化 ≤1 次/分钟；不做动画或分钟级倒计时（FULL 刷新约 2.2 s，计数 +1）。
- 每阶段以「预览 + 真机 + 证据文档」结束；超过 2 个会话就砍范围或拆分。
- 外部依赖失败不阻塞主线：LKG + stale 是页面的一等状态。
- 天气源、农历数据表、依赖版本钉住并写测试。

## 9. 成功指标

- 6 页均可选、均在真机出现 `200→304`，切页 ≤2 个轮询。
- 天气断网保留上一帧并标 stale；日历经 3 个含节气/节假日日期正确。
- Codex 数字来自真实同步；刷新计数每次内容变化恰好 +1。
- 两套测试全绿；每页在 `PROJECT_STATE.md` 有 PASS 段；本地与 `origin/main` 一致（经授权）。

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 天气源变更/证书问题 | 单一源 + 超时 + LKG；失败只标 stale，不阻塞其他页面 |
| 农历/节气算法错误 | 固定测试日期（春节、闰月、节气、中秋/除夕）；调休数据暂不含 |
| Codex 数据源不可用 | 同步脚本失败保留上一帧；页面显示上次更新时间 |
| e-ink 刷新代价被低估 | 频率上限写进验收门；倒计时/动画明确拒绝 |
| 范围膨胀 | 一次一页；超 2 个会话即拆分 |
| 设备端功能期待 | 本文件第 3 节即答复：v1 不改固件 |
